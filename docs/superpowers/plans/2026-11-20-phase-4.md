# Phase 4 — Release v1.0.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Đảo Đèn Lồng v1.0.0 with an automated benchmark, a 10-night soak test, a disk-backed leaderboard, accessibility options, and release docs.

**Architecture:** A `benchmark` flag on the pure `Game` core freezes damage/spawn/decay while leaving shade wander intact, so a Playwright-driven `bench.html` measures the real Three.js renderer. A Node CLI serves the built UI plus a JSON leaderboard API and also exports that file. Soak runs 10 nights in one Node process with seeded random input.

**Tech Stack:** TypeScript 7, Three.js 0.187, Vite 8, esbuild, Vitest 5, Playwright 1.65, Node 20+.

**Spec:** `docs/superpowers/specs/2026-11-20-phase-4-design.md`

## Global Constraints

- Gameplay tuning, tick order, snapshot/event fields and existing JSONL output must not change.
- `src/core/**` must not import DOM, Three.js or Node APIs; randomness only via `Rng(seed)`.
- `game.contract.json` tuning must equal `TUNING` exactly.
- Contract version is `1.3`; `bench_cmd` and `soak_cmd` are required fields.
- Benchmark: 1280×720, seed 42, 200 wander shades, 100 motes, L1–L3 lit at 100 fuel, 3 s warmup, orbit camera r=30, y=15, 15 s/revolution.
- Soak: 10 nights, order 1→2→3, night i seed `7+i`, `crashes = 0`, `mem_end_mb <= 1.2 × mem_start_mb`.
- Leaderboard: name 3–12 chars `[A-Za-z0-9_]`, top 10, score desc, ties keep arrival order, `achieved_at` ISO 8601 with timezone.
- UI text at least 18 px at 1280×720; large-text option ×1.25.
- No committed player data (`data/`), no secrets, `node_modules/`, `dist*/` stay ignored.

## Review Focus

- A player renames a key to one already bound: the UI must reject the assignment, name the conflicting action, and keep the old binding working.
- The disk API is unreachable (static hosting or server stopped): the leaderboard must still load and save via `localStorage` and never throw.
- A leaderboard file is corrupt or hand-edited: reads must yield `[]` instead of crashing the app.
- A tie in score: the earlier entry must stay above the later one after re-insert and after reload.
- Benchmark on a machine without the Playwright browser: the script must print one actionable line and exit non-zero instead of hanging.
